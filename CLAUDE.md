# facteur-ts

Transactional mailer for the Facile Suite (TypeScript): confirmations,
notifications, resets. `nodemailer` is the only runtime dependency.

Sibling repo [facteur](https://github.com/FacileStudio/facteur) is the Go
implementation. One `SMTP_*` env convention across both.

## Tech Stack

- TypeScript 5.8, NodeNext, tsc build, package `@facile/facteur`.

## Layout

```
facteur-ts/
  src/
    index.ts         # fromEnv, createMailer, createMemoryMailer
    index.test.ts
  package.json       # @facile/facteur
  tsconfig.json      # excludes *.test.ts from the published build
  dist/              # Compiled output (committed, generated by tsc)
  README.md
  CLAUDE.md
```

## Conventions

- **Env vars**: `SMTP_HOST`, `SMTP_PORT` (default 587), `SMTP_USER`, `SMTP_PASS`,
  `SMTP_FROM`. Identical names in facteur — one ops doc.
- **No host configured ⇒ refuse, don't swallow**: send rejects with a
  "not configured" error. The app decides log-and-continue vs fail-closed.
- **Test seam**: `createMemoryMailer()` records messages instead of sending.
  Tests assert on what would have been sent, no transport needed.
- **Text part always present**: empty `text` is auto-filled by stripping HTML.
- **Scope**: transport + message shaping only. No templates, no queue.

## Key Commands

```bash
bun test && bun run build
```

## Gotchas

- Port 465 = implicit TLS; any other port = plain + STARTTLS when offered.
  Plain auth only when `SMTP_USER` is set.
- `dist/` is committed for git installs (`bun add github:FacileStudio/facteur-ts#main`);
  rebuild after changing `src/`.
- The Go package is `mailer`; the TS package name is `@facile/facteur`.
